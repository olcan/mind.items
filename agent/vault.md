#agent/vault is a _vault chat agent_: the request/reply protocol of a _[chat](#chat) agent_, with a vault host behind it instead of a model api. Tag a chat item `#agent/vault` (visible or hidden) and end it with a `\<<user>>` message; a listener on the vault host appends a signed reply, e.g. `\<<agent('vault/default')>>`. Since 2026-09-10 the vault has ONE owner-facing persona: `/vault` (#chat/vault) starts the default persona, a Claude Fable 5.1 SUPERVISOR that is read-only at the vault root and gets the actual work done through a worker it starts (writable in the chat's own worktree, the web tools as its only network path, the app submodules populated; registry cost limits $10 per supervisor turn and $30 per worker run), waits for, and reports on; the owner talks to the supervisor only, sees its status and progress on the chat item and on #vault, and merges the chat's proposal through #vault or by telling the supervisor to (design `notes/design/mind_vault_supervisor.md` in the vault). Persona sub-tags (`#agent/vault/<name>`) still select a registry name on the trusted side, but every other name is retired: conversations under `#agent/vault/fable`, `#agent/vault/fable_wt`, `#agent/vault/fable_dev`, and `#agent/vault/supervisor` stay readable and are no longer requests (nothing is paid, nothing replies); an unknown persona gets no reply either. Failures are replies too, so no request dies silently.

The legacy route `#agent/native` remains a read alias indefinitely: dormant conversations under the old tag keep working, but new items should use `#agent/vault`.

Status: **live**. The v2 dispatcher (`bin/mind_bridge_v2.py` in the vault repo, registry in `agents/bridge.toml`) has run in production on the vault host since 2026-08-30 (owner-started, explicit `--production` mode with service-account credentials, per-account hard checks, and a domain lock), dispatching real persona runs and appending signed replies as readable inert regions (the `<!--inert-->` format, cut over 2026-08-31). The original echo PoC executor (`bin/mind_bridge.py`) and its emulator e2e listener rows are retired; end-to-end evidence lives in the vault's Firestore-emulator component smoke and the recorded production canary.
